Существующие проблемные места:

1. Система не справляется с постоянно растущим потоком заказов;
2. Отсутствуют качественные инструменты мониторинга, которые позволили бы определить конкретные причины из-за которых:
    А. ETA заказов регулярно не выполняется;
    Б. Производственные мощности задействованы только на 50%;
3. UI MES не обеспечивает должное быстродействие при работе операторов с приложением;
4. Задержки релиза

Потенциальные проблемные места:

1. Только один экземпляр MES API для обработки всех входящих запросов на расчет стоимости;
2. Слабый уровень React экспертизы в команде, могут потребоваться доработки на стороне фронтенда MES;
3. Ручные CI\CD процессы
4. Всего один тестировщик в команде
5. Отсутствие интернет-портала для юрлиц (АПИ-юзеров) - проще и безопаснее убрать прямой доступ к АПИ и предоставить единую точку входа для всех клиентов

Инициативы:

Ключевой проблемой является недостаток наблюдаемости системы, поэтому наиболее приоритетными будут инициативы, направленные на устранение данного недостатка:

        1. Внедрение мониторинга 
                - Производительности компонентов системы, в первую очередь - брокера сообщений и MES API [Приоритет - 1]
                - Показателей системного уровня [Приоритет - 2]
                - Бизнес-показателей: темп роста заказов, среднее время жизни заказа и т.д. [Приоритет - 3]

        2. Внедрение трейсинга заказов от момента завершения оплаты до отправки готового изделия [Приоритет - 1]

Чуть менее критичной, но также требующей быстрого решения является проблема с интерфейсом MES. 
Скорее всего, внедрение фильтров и пагинации не решило проблему долгой загрузки первой страницы так как весь массив данных все еще выгружается напрямую из БД. Поэтому:

        3. HTTP-кеширование для MES - поможет ускорить загрузку страницы, т.к. большая часть заказов (кроме самых новых) будет возвращаться из кеша. [Приоритет - 2]

Проблему с задержками релизов можно решать путем постепенного внедрения автоматизации в процессы тестирования и деплоя, и начать с:

        4. Разработки автотестов для QA среды (вероятно, потребуется нанять еще одного тестировщика), [Приоритет - 3]

Любые другие инициативы по доработке системы следует рассматривать только на основе конкретных данных, полученных в результате анализа метрик. 

Три ключевых пункта: мониторинг производительности MES API \ трейсинг заказов \ кеширование для MES.
