*Предлагаемое решение*

Для надежности, создадим трейсинг на протяжении всего жизненного цикла заказа.

Будем использовать: 
    - OpenTelemetry SDK для сбора данных и метрик, и отправки в Jaeger и Prometheus соответственно; 
    - Jaeger для обработки и визуализации трассировок (Jaeger UI)

Трейсинг должен покрыть следующие операции:

1. Интернет-магазин (Shop + Shop API) 
    - сущность "заказ" на этапе создания [SUBMITTED] имеет все необходимые для дальнейшей обработки атрибуты 
    - данные по заказу корректно переданы CRM-системе

2. CRM
    - Проверка полноты и корректности атрибутов заказа, полученного из Интернет-магазина
    - Проверка корректного смены статуса заказа после завершения оплаты [MANUFACTURING_APPROVED]
    - Данные по заказу корректно переданы в MES
    - Проверка корректного смены статуса заказа после подтверждения доставки [CLOSED]

3. MES
    - Проверка полноты и корректности атрибутов заказа, полученного из CRM
    - Проверка корректного смены статуса заказа после принятия в работу [MANUFACTURING_STARTED]
    - Проверка корректного смены статуса заказа после завершения производства [MANUFACTURING_COMPLETED]
    - Проверка корректного смены статуса заказа после начала упаковки [PACKAGING] и отправки на доставку [SHIPPED] - данные корректно переданы в Shop для отображения в ЛК клиента


*Мотивация*

Трейсинг даст компании возможность: 
    1. отследить и скорректировать (поменять статус вручную, добавить недостающие атрибуты и т.д.) жизненный цикл любого заказа 
    2. оценить качество интеграции между различными компонентами системы, найти зоны улучшения

*Компромиссы*

Трейсинг не принесет пользы, если: 
    1. результаты мониторинга позволят обнаружить все источники текущих проблем еще до внедрения трейсинга;
    2. у компании не будет ресурсов (в т.ч. компетенций) на исправление обнаруженных трейсингом проблем;
    3. он создаст уязвимость в системе, которой воспользуются кибер-преступники (*аспект безопасности* - админские права на работу с инструментами мониторинга и трейсинга следует выдавать только определенной команде, например - QA. Остальные заинтересованные могут ограничиться получением регулярных отчетов.)
